# data · 数据来源与分片仓库

存放**网络核对所用的大数据源的加工结果**。原始文件体积大（如 12306 官方快照约 15MB），故按逻辑分片后存入本仓库，便于追溯与复算，网页本身并不加载这些文件（站点仍由 `index.html` 单文件承载）。

## 目录结构

```
data/
├─ README.md                        # 本说明
├─ 12306-trainlist/
│  └─ 2022-08/                      # 12306 官网车次快照（含起止站），按字头分片
└─ 12306-derived/
   └─ 2025/                         # 2025 现行车次→train_no 对照，按字头分片
```

## 车次字头分片（两套）

### A. `12306-trainlist/2022-08/`（含起止站）

- 来源：12306 `train_list.js`（官网）；快照 2022-08-19 ~ 08-29（16 天）
- 加工：聚合 → 按 `station_train_code` 去重（**12,996**）→ 按字头分片；一行一条 `车次(起站-止站)`
- 体量：**约 356KB**（原 15MB）

### B. `12306-derived/2025/`（现行车次 + 内部车次号）

- 来源：`wj0575/RailRhythm12306` 的 `train_data/no_list*.json`（**21 个快照日，2025-01-18 ~ 07-06**）聚合
- 加工：跨日去重（**22,258** 现行车次）→ 按字头分片；一行一条 `车次 ⇥ train_no ⇥ 出现天数`
- 说明：第三方仓库（GPL-3.0，仅供对照）。**缺起止站**——需与 A 套 `train_list.js`（2022）配合：2025 定「现行车次」，2022 补「起止站」
- 体量：**约 550KB**（第三方原始约 7.2MB/月，归属仓库 348MB）

> 两套合计约 `data` 928KB。**原始信息损失说明**见仓库主 `README.md`「数据来源与核验」。

### C. 数据加工流水（复算入口）

> 加工脚本用脚本化生成，仅记录、不入库（走 `.gitignore`）。复算路径：`train_list.js`（官网）→ `validate/data 预处理`；`no_list*.json`（2025）→ 聚合去重 → 字头分片。若要复算本仓库两套 txt 与 MANIFEST，可按上文「加工」描述在本地重跑（原始来源 URL 在 MANIFEST 内）。
