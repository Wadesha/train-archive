# 火车档案 · Train Archive

一个**单人、单文件（`index.html`）**的中国铁路档案应用。整个站点只有这一个 HTML：数据层、路由、全部视图渲染、甚至「数据库」都打包在其中，无构建步骤、无后端、无第三方依赖。浏览器直接打开就能用，托管到 GitHub Pages 后即为完整站点。

本文既是一份使用说明，更是一份**完整的项目思路记录**——从为什么要做、数据从哪来，到每一步架构决策是怎么一步步演化成的，全部写在这里。

---

## 一、为什么要做这个东西？

面向铁路爱好者的**车站 / 线路 / 列车**三维档案库。铁路信息散落在 12306、新闻、爱好者社区，缺一个把「真实而完整」的车站与车次聚到一处、还能持续沉淀的地方。

几个从一开始就定下的原则：

1. **单体极简**——不求架构宏大，只求随处可跑、永久可读。`index.html` 双击即开，拷走即带走。
2. **数据真实第一**——能用官方来源（如 12306 的 `station_name.js`）就用官方来源；查不到的明确标注「无记录 / 乘降所 / 境外站」，**绝不编造**。
3. **数据要「全」，也要「准」**——完整性靠全量抓取，准确性靠联网校对（更名、乘降所状态等）。
4. **面向未来留口子**——为「全球火车档案」预留扩展，而不是等到需求来了再推倒重来。

## 二、数据从哪来？（数据层思路）

这是整个项目最关键的一步。

### 2.1 车站元数据：12306 官方动态文件

车站名、电报码、全拼/短码、城市、序号——这些来自 12306 前端动态加载的 `station_name.js` 静态文件。它包含了 **3384 个车站**的官方登记信息，是相对可靠的全量来源。

起初业务逻辑尝试直接抓 12306 车次接口，但接口频繁以 403 拦截；于是改走 **`station_name.js` 静态文件**提取车站数据，绕开接口限制，反而拿到了更稳定的基层数据。

### 2.2 从「全量」到「本档案」：匹配思路

档案没有把所有 3384 个站直接堆上去，而是**匹配本档案实际用到的车站**：

- 抓全量 3384 站 → 与本档案使用的车站做关联 → 为 **162 个实际使用车站**补全电报码 / 拼音 / 城市等元数据。
- 处理新老站名冲突，用「精确 → 包含 → 反向」三级匹配兜底，例如更名站 `甘洛 → 甘洛南`。
- 匹配不上的如实处理，不硬凑数据。

### 2.3 真实验证：不替官方做决定

- **更名车站**：如 `松江南` 已按 2024 年铁路公告更新为 **`上海松江站`**（电报码 `IMH`）。
- **乘降所**：如 5619 次慢车经过的 `尼日、苏雄` 等站，12306 查不到记录。这类**公益慢车**的真实停站我们对照社区与票务数据补全，并标注「乘降所（12306 无记录）」——数据补全，但诚实说明来源。
- **境外站 / 跨境站**：标注「国际列车境外站」，绝不误配国内电报码。曾发现 `下普雄` 被误配过电报码，已修正为不配码、仅保留城市与说明。

> 一句话：**完整性来自全量抓取，可信度来自逐项核验与如实标注。**

## 三、架构怎么一步步演化？（从 v1 到现在的思路演进）

这个项目不是一步到位的，是顺着用户需求一层层长出来的。

### 阶段一：基础档案（车站 / 线路 / 列车 三视图）
- 单文件 SPA，hash 路由（`/`、`/lines`、`/trains`、`/stations`、`/contribute`）。
- `localStorage` 持久化 + 就地编辑 / 投稿。

### 阶段二：用 12306 数据把车站补「全」
- 引入 `station_name.js` 全量抓取与匹配，补全电报码 / 拼音 / 城市。
- 引入**特殊车站标注**（乘降所 / 境外站 / 更名站），从「有名字」进化到「有可核验的档案」。

### 阶段三：待开通车站专题
- 既然 12306 只有已开通站，**在建设中的站**就单独做成专题：
  - 新建 `UPCOMING_STATIONS` 数据集，收录 **96+ 在建 / 拟建车站**。
  - **开通时间临近自动置顶**（倒计时窗口在最上），按年份/阶段分组（倒计时 / 一年内 / 1–3 年 / 远期）。
  - 提供**省份卡片**：按 34 个省级区划自动归类 `city` 黏连名（如 `河北雄安`、`上海嘉定`），点击卡片跳转该省待开通车站列表。

### 阶段四：待开通线路专题 + 多对多关系
- 新建 `UPCOMING_LINES`，收录 **26 条在建 / 拟建线路**，并按通车年份分组。
- **线路 ↔ 车站 多对多**：一站可以属于多条线（如上海东站、宝山站、天府站南场）。建立**双向索引**，在同一铁路档案下，同一枢纽站会出现在其所属的每一条线路中，并带 `+N` 角标与「共用枢纽站」识别；点击线路里的车站标签可反向跳到待开通车站页的对应站。

### 阶段五：国际 / 全球架构预留
- 中国有跨境国际列车（如 K3/K23/K27、经二连/满洲里/丹东/凭祥/河口出境），但**当前档案主国是中国**。
- 因此设计了 `GLOBAL_SCOPE` 常量作为**预留结构**：`enabled` 开关（默认 `false`）、`record`（国内 / 跨境 / 境外三档）、`corridors`（中蒙俄 / 中朝 / 中越三条走向）。
- 跨境/境外车站用 `scope` + `country` 字段标注，在详情页显示「跨境」徽章。
- **未来把 `enabled` 切为 `true`、扩充 `corridors` 即可无缝升级为全球火车档案**——今天只做结构预留 + 标注中国跨境，不为假想的未来写过度的代码。

> 架构思路主线：**先让单一事实源（车站档案）扎实可信 → 再做「待开通」这类官方数据之外的长尾 → 用多对多关系承载真实世界 → 最后为全球化预埋开关。**每一步都不是推翻重来，而是在同一份单文件里自然地加一层。

## 四、页面与路由（hash 路由）

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/` | 首页 | 车站 / 列车概览 + 全局搜索 |
| `/lines` | 线路档案 | 中国铁路线路 |
| `/trains` | 列车档案 | 运营车次（现行 / 已停运） |
| `/stations` | 车站 | 车站明细，含 12306 电报码 / 拼音 / 城市元数据，跨境 / 境外标注 |
| `/upcoming` | **待开通车站** | 96+ 在建车站，倒计时置顶、按年份/阶段分组，省份卡片筛选 |
| `/upcoming-lines` | **待开通线路** | 26 条在建 / 拟建线路，与车站多对多关联 |
| `/contribute` | 投稿 | 提交新线路 / 列车 |

**查询参数（供专题页跳转定位）**：
- `#/upcoming?prov=山东` → 只显示山东省待开通车站
- `#/upcoming?focus=临清东` → 定位到该站行（多对多跳转用）

## 五、技术实现要点

- **单文件 SPA**：`index.html` 内含数据常量、`GLOBAL_SCOPE`、`UPCOMING_STATIONS`、`UPCOMING_LINES`、`STATION_REGISTRY`（动态生成的车次-车站索引）、hash 路由 `route()`、以及所有视图渲染函数。
- **关系模型**：站的 `STATION_META` 与线路/列车通过关键字匹配动态合成注册表；待开通线路↔车站用独立的 `upcomingLinesOfStation()` 反查索引，实现多对多双向。
- **数据合并**：`mergeStationMeta()` 把 `scope` / `country` / 电报码 / 拼音等合并进最终注册表，保证一处定义、处处复用。
- **可测性**：`index.html` 内嵌 JS 通过 `node validate.js` 做语法校验；`test_upcoming.js` 用 Node `vm` 沙箱模拟 DOM 做数据 + 渲染断言（当前 43 项全过）。本地开发校验脚本不入库。

## 七、文件结构

```
index.html   # 唯一发布文件：数据层 + 路由 + 全部视图渲染
data/        # 网络核对所用大数据源的「按逻辑分片」加工结果（详见 data/README.md）
README.md    # 本文（使用 + 完整思路）
```

> `data/` 下的分片（如 `12306-trainlist/2022-08/*.txt`）由约 15MB 的 12306 官方快照去重、按车次字头分片而来，仅作追溯与复算，网页不加载它们，站点仍为单文件。
> `.gitignore` 中的 `validate.js` / `test_upcoming.js` / `prototype-*.html` 为本地开发与校验脚本，不入库，仅用于开发。

## 八、数据来源与核验

车站元数据来自 12306 `station_name.js`；车次快照来自 12306 `train_list.js`（官网，约 15MB，快照 2022-08），并按字头分片存入 `data/12306-trainlist/`。核验结论直接落进档案——列车详情页的「**核验来源**」标注即由这些快照交叉核对得出（如 G1/G7/D901/T109/Z21/T49/5619/K27/Z5/D717 的起止站已核，K3 为国际联运不在普通车次表，Z9/Z97 已停运故快照中确实缺省）。历史数据分析文献：`sjfkai/grab12306`、`wj0575/RailRhythm12306`（后者的 2025 年逐日快照时效更新，仅供对照，本仓库未转载）。

## 九、未来演进（Roadmap）

- **待开通数据持续校准**：各线开通时间随官方公告滚动更新，动态化开放年份。
- **更多元的车站属性**：运营状态（接驳 / 大修 / 关闭）、历史沿革时间线。
- **全球化**：将 `GLOBAL_SCOPE.enabled` 置为 `true`，按走廊扩充 `corridors` 与国际车站 `country`。
- **导出 / 离线**：一键把 `localStorage` 数据导出为 JSON / Markdown，方便长期归档。
